# Тестирование downstream-сервиса с internal-identity

Библиотека называется `internal-identity` (`com.spimex:internal-identity`). Она
читает из HTTP-заголовков UUID пользователя и версию его записи и не зависит
от Spring или Servlet API. Ниже предполагается, что библиотека уже подключена
к вашему сервису.

## Какие заголовки передавать

Источник контракта — класс
[`IdentityHeaders`](../src/main/java/com/spimex/identity/IdentityHeaders.java).
Названия доступны в константах `IdentityHeaders.USER_ID` и
`IdentityHeaders.USER_VERSION`. Краткое описание библиотеки есть в её
[README](../README.md).

| Заголовок | Значение | Пример |
| --- | --- | --- |
| `X-Internal-Identity-User-Id` | UUID пользователя (`User.id`) | `11111111-1111-4111-8111-111111111111` |
| `X-Internal-Identity-Version` | Версия записи пользователя: целое число типа `long`, не меньше нуля | `0` |

Оба заголовка обязательны. Логин, email, роли и разрешения в этот контракт
не входят. Если ваш сервис использует UUID для поиска данных, подготовьте
тестовые данные для этого пользователя. UUID и версия выше — условные значения;
для сценариев с реальными данными используйте соответствующие `userId` и
`userVersion` из разрешающего ответа user-service.

## Отправить запрос напрямую в локальный сервис

Запустите downstream-сервис и отправьте запрос на его адрес, указав оба
заголовка. Например, в PowerShell:

```powershell
curl.exe -i "http://localhost:8082/api/orders" `
    -H "X-Internal-Identity-User-Id: 11111111-1111-4111-8111-111111111111" `
    -H "X-Internal-Identity-Version: 0"
```

Замените порт и путь на адрес проверяемого endpoint. Метод, тело и остальные
заголовки задаются по API вашего сервиса. В Postman добавьте эти две пары
имя/значение на вкладке **Headers** и отправьте запрос на тот же адрес.

Ручная подстановка имитирует запрос от gateway и подходит для локального
тестирования downstream-сервиса. В рабочем окружении эти заголовки формирует
gateway после аутентификации и успешной проверки прав; доступ к сервису должен
быть ограничен доверенной сетью. Библиотека проверяет формат заголовков, но
не удостоверяет отправителя и не проверяет существование пользователя или права.

Для проверки полного пути через gateway отправляйте запрос на адрес gateway
с действующим JWT в `Authorization: Bearer <token>`. Маршрут должен быть настроен,
а пользователь — иметь требуемое разрешение. Gateway сам подставит внутренние
заголовки и перезапишет переданные клиентом значения.

## Извлечь пользователя в сервисе

В обработчике HTTP-запроса передайте библиотеке функцию чтения заголовка.
Для Servlet API (`jakarta.servlet` или `javax.servlet`):

```java
import com.spimex.identity.IdentityHeaders;
import com.spimex.identity.InternalIdentity;

import java.util.UUID;

// request — HttpServletRequest текущего запроса.
InternalIdentity identity = IdentityHeaders.read(request::getHeader);
UUID userId = identity.getUserId();
long userVersion = identity.getUserVersion();
```

`userId` — стабильный идентификатор пользователя для дальнейшей бизнес-логики.
`userVersion` — версия его записи, а не версия токена или протокола.
Библиотека только извлекает эти два значения: дополнительную информацию
о пользователе сервис получает отдельно, если она нужна его сценарию.

Для Spring `HttpHeaders` и обычной `Map<String, String>` соответственно:

```java
InternalIdentity identity = IdentityHeaders.read(httpHeaders::getFirst);
```

```java
InternalIdentity identity = IdentityHeaders.read(headers::get);
```

В обычной карте используйте ключи из `IdentityHeaders`: поиск в `Map`
может быть чувствителен к регистру.

## Подготовить заголовки в автоматическом тесте

Чтобы не дублировать названия и сериализацию, сформируйте карту библиотекой
и передайте её заголовки в используемый HTTP-клиент или тестовый запрос:

```java
import com.spimex.identity.IdentityHeaders;
import com.spimex.identity.InternalIdentity;

import java.util.Map;
import java.util.UUID;

InternalIdentity testUser = new InternalIdentity(
    UUID.fromString("11111111-1111-4111-8111-111111111111"), 0L
);
Map<String, String> headers = IdentityHeaders.write(testUser);
```

При успешном запросе проверьте, что бизнес-логика получила ожидаемые UUID и
версию. Также проверьте отказ при отсутствии любого из заголовков,
некорректном UUID, нечисловой или отрицательной версии.

`IdentityHeaders.read(...)` выбрасывает `IdentityHeaderException`; метод
`getReason()` возвращает `MISSING_USER_ID`, `INVALID_USER_ID`,
`MISSING_USER_VERSION` или `INVALID_USER_VERSION`. Преобразование ошибки
в HTTP-ответ выполняет ваш сервис: библиотека не задаёт HTTP-статус.
При ошибке чтения не продолжайте обработку как для идентифицированного
пользователя.
